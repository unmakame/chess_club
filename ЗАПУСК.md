# Как запустить bbchess

Если на этом компьютере клуб уже работает, откройте [игровой зал](http://localhost:8080). В PowerShell браузер можно открыть командой `Start-Process "http://localhost:8080"`. Если браузер сообщает, что соединение отклонено, запустите сервер по шагам ниже.

## 1. Подготовьте Docker

| Система | Что понадобится |
|---|---|
| Windows | [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/) в режиме Linux-контейнеров. Выполните указания установщика по WSL 2, затем откройте Docker Desktop. |
| macOS | [Docker Desktop для Mac](https://docs.docker.com/desktop/setup/install/mac-install/). Выберите сборку под процессор вашего Mac и запустите приложение. |
| Linux | [Docker Engine](https://docs.docker.com/engine/install/), [плагин Compose](https://docs.docker.com/compose/install/linux/) и OpenSSL. Запустите службу Docker. |

Дождитесь готовности Docker. Откройте новый терминал и выполните:

```text
docker --version
docker compose version
docker info
```

Первые две команды выводят версии, третья должна показать раздел Server. Первой сборке нужен интернет для скачивания образов и библиотек. Python, React и PostgreSQL устанавливаются внутри контейнеров.

## 2. Перейдите в папку проекта

**На текущем компьютере с Windows** откройте PowerShell:

```powershell
cd "$HOME\Desktop\chess_club"
Get-ChildItem compose.yaml, start.ps1, frontend
```

**На Linux или macOS** откройте терминал в каталоге проекта. Например, если папка лежит в Desktop:

```sh
cd "$HOME/Desktop/chess_club"
ls compose.yaml start.sh frontend
```

Если проект лежит в другом месте, подставьте его путь. Для переноса текущей версии на другой компьютер возьмите исходники из рабочей папки, включая frontend, static, templates, sql, Dockerfile и стартовые скрипты. В копии с GitHub будут только отправленные туда изменения. Для новой установки скрипт создаст собственный файл с паролями.

## 3. Запустите сайт и базу

**В Windows PowerShell** выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

**На Linux или macOS** выполните:

```sh
sh ./start.sh
```

Скрипт создаст файл `.env` при первом запуске. Docker соберёт React, запустит PostgreSQL, применит миграции и включит веб-сервер и фоновую обработку броней. Дождитесь завершения команды и откройте **[http://localhost:8080](http://localhost:8080)** в браузере этого компьютера. После успешного запуска терминал можно закрыть.

## 4. Проверьте результат

1. На свежей базе «Игровой зал» показывает 24 стола. Нажмите на свободный стол и выберите интервал.
2. Откройте [рейтинг клуба](http://localhost:8080/ratings). В демонстрационных данных первое место занимает Магнус Карлсен.
3. Для проверки записи выберите доступный интервал в рабочий день, например с 12:00 до 13:00 по Москве. Укажите посетителя, тариф и нажмите «Удержать стол на 10 минут». В карточке появится номер брони. После обновления страницы бронь должна остаться.

Состояние сервисов можно проверить из папки проекта:

```text
docker compose ps -a
```

У `db` ожидается состояние `healthy`, у `web` и `worker` — `Up`. Для `migrate` нормален результат `Exited (0)`: этот сервис завершает работу после применения миграций.

## 5. Остановка, повторный запуск и обновление

| Действие | Команда из папки проекта |
|---|---|
| Остановить клуб с сохранением базы | `docker compose down` |
| Снова запустить клуб | `docker compose up -d web worker` |
| Пересобрать после изменений в React, Python или SQL | `docker compose up -d --build web worker` |
| Посмотреть последние сообщения сервисов | `docker compose logs --tail=80 db migrate web worker` |

Брони и посетители хранятся в именованном томе Docker. Сохраните исходный `.env` этой установки. Опция `-v` у команды остановки удаляет том вместе с данными. Если раньше сайт работал с PostgreSQL вне Docker, контейнерная версия создаст отдельную базу с демонстрационными записями.

## Если запуск остановился

| Сообщение или симптом | Что сделать |
|---|---|
| Команда docker не найдена | Установите Docker, откройте новый терминал и повторите шаг 1. Стартовый скрипт сам Docker не устанавливает. |
| Cannot connect to the Docker daemon | Запустите Docker Desktop или службу Docker Engine. Дождитесь успешного ответа docker info. |
| Не найден скрипт или compose.yaml | Повторите шаг 2. Проверьте, что терминал открыт в корне chess_club. |
| Port is already allocated / address already in use | Откройте localhost:8080: возможно, клуб уже работает. Для второй копии замените в compose.yaml строку `127.0.0.1:8080:8080` на `127.0.0.1:8081:8080`, повторите шаг 3 и откройте [localhost:8081](http://localhost:8081). |
| На Linux не найдена команда openssl | Установите OpenSSL через менеджер пакетов дистрибутива и повторите запуск. |
| Миграции завершились с ошибкой | Посмотрите `docker compose logs --tail=80 db migrate`. При ошибке пароля для существующего тома проверьте исходный .env. |
| После изменения дизайна виден старый интерфейс | Выполните пересборку из шага 5 и обновите страницу. Проверьте порт, если запущены две копии. |

## Проверка перед защитой

После запуска выполните по очереди:

```text
docker compose run --rm migrate python web_checks.py
docker compose run --rm migrate python bench.py --rows 100000
```

Первая команда проверяет приложение в отдельной тестовой базе. Ожидаемый итог — `OK`. Сообщение об отклонённой строке CSV входит в проверку импорта. Вторая команда выводит сравнение трёх запросов до и после создания индексов. Сверка с техническим заданием приведена в [README](README.md).
